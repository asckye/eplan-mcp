# ADR-0041：对 not_applicable 签名区分协议适配与架构边界

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（2026-11-01 接受） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；接受后按本文边界逐组实施 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **0 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

正式缺口内本类首阻和签名数均为 0；目录分母外有 359 组 not_applicable，含运算符/转换等签名及 overlay 排除的远程架构接口。例子是 `AnyPropertyId.op_Implicit`；普通可用的 `AnyPropertyId.As*` 属性仍在 B2，不应混为排除。

把运算符当普通方法会造成签名消歧、转换/副作用和返回类型错误；显式接口或派生上下文可能不可构造。远程客户端/服务器类改变进程拓扑、端口与权限边界，不能用“可适配 JSON”绕过 ADR-0002/0032。

## 提议的安全调用方式

1. 逐签名核对排除原因：纯值转换可研究有类型 DTO 输入/输出和编译表达式，限制数值、枚举和数组大小；显式接口只能通过公开实现实例及已验证转换调用，不能使用私有反射或提交任意对象。
2. 有潜在项目写入的转换仍进入 scratch 的逐次审批、快照和事务；审批展示实际转换表达式/精确签名及目标，不能把它降为目录查询。先只读、再根据证据登记写级别；替代功能不计作原组已直接调用。
3. 纯协议形状可适配不表示架构上应接入远程类。远程拓扑、脚本/委托、自建宿主等先写具体 L3 方案，由负责人另行确认，不改变当前已接受架构。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

抽象实例不能直接构造；没有具体公开实现的显式接口不能伪造；任意委托、代码或模型传 native 对象不进入通用工具。API 本身未提供的语义不能靠序列化创造。证据缺失保留待查，不判定整类永久不可能。

## 备选方案与代价

维持排除无需新协议；全部按反射方法开放会破坏封闭分发表；逐签名值适配能补真缺口，但远程架构仍必须走独立决策。

## 需要项目负责人决定

是否接受只研究有明确公开语义的类型转换/显式接口适配？哪些 not_applicable 是必须维持的架构边界？是否确认 359 组仍不计入 4014，扩大目标须另定范围，不能为增加百分比修改分母？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。接受前不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 决定（2026-11-01）

项目负责人 2026-11-01 确认原话：“按你推荐的来，接受 ADR-0036 到 0045”。按本文“提议的安全调用方式”接受；“仍不能开放的部分”继续排除，也不抵充 4014 完成数。所有候选仍默认关闭，按随产品审阅的精确编译分支逐组开放；逐次审批、scratch 限定与实机验证要求不变。本决定只接受本类别的审阅边界，逐组例外仍须留下批准记录。

## 后续验证与依据

Small 验证溢出/非法枚举/歧义与明确转换；Medium 验证非公开实现和任意对象被挡；确有运行时行为的获准签名安排 scratch Large，远程/拓扑变化另列设计和测试。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
