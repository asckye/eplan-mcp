# ADR-0037：为交互与会话状态调用建立隔离、恢复和模态取消边界

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（2026-11-01 接受） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；接受后按本文边界逐组实施 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **253 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

包括 `Ged.Interaction.OnPoint/OnCancel`、`SelectionSet.Selection`、`Edit.SelectObjects`、`DrawingService.DrawDisplayList`、`ChangeInfoService.SetActive`、`EplApplication.OpenProjectDlg/Exit`、进度、事件和事务/锁上下文。B5 的 `SetMainFrame(IntPtr)` 也须满足本 ADR，但不重复计组。

当前选择、活动页、锁、事件订阅及静默模式属于实例共享状态；参数可能落在真实项目。模态窗口可阻塞 EPLAN 主线程，Host 超时不等于调用停止；退出、重建事务上下文或错误回调顺序还可能破坏未保存工作。A61 只证明个别 action，不证明这些 API 的交互行为。

## 提议的安全调用方式

1. 先做无副作用的状态读取，写/交互只在没有其他项目或人工编辑的隔离测试实例中逐条开放；执行前确认仅目标 scratch 已打开且为当前项目。保存选择、活动文档、临时模式、锁及订阅清单；可恢复者执行后恢复并核对，无法恢复者要求隔离实例可丢弃，审批必须写明限制。
2. 独立审批列出“影响整个 EPLAN 实例/当前窗口”、会改变的状态、是否出现对话框、最长等待及退出/丢弃风险，绑定目标实例和状态快照。不能把 `On*` 回调直接当普通命令随意调用：须由受控交互驱动器提供合法顺序、上下文及事件参数；不接受模型提交委托或窗口地址。
3. 提议模态看门狗在不会被同一 EPLAN 主线程阻塞的位置观察窗口，只识别与本次实例和调用绑定、事先验证可取消的对话框，超时自动 Cancel。不得按通用 Enter/Yes、不得处理审批窗口、不得点击确认产生业务写入；不认识的窗口只告警并记 unknown、暂停实例。
4. 取消只是恢复尝试；必须查询原调用是否结束，再检查项目与共享状态。不能安全取消时保留 unknown 及暂停，不自动重试写入或强杀用户实例。若看门狗实现要求新的进程拓扑/权限，先将具体设计与故障路径交负责人再次确认。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

项目事务无法逆转已经结束进程、释放的外部资源或被其他用户观察的状态。没有合法上下文/事件驱动器的受保护回调不能靠反射硬调。不能保证任意模态窗口均可自动取消，也不提供自动批准或强杀用户 EPLAN 来伪装回滚。

## 备选方案与代价

维持交互排除使这一类继续不可调用；人工预先打开窗口只能解决特定前置条件；盲目点击对话框容易批准非预期写入；可丢弃的测试实例恢复成本较高，但适合无法事务回滚的会话行为。

## 需要项目负责人决定

是否接受隔离测试实例及调用后恢复？哪些交互允许自动 Cancel、哪些只允许读取？是否允许退出等不可恢复操作仅作用于可丢弃实例？是否接受看门狗的权限/部署方式需另审，以及取消失败后的 unknown 暂停流程？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。接受前不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 决定（2026-11-01）

项目负责人 2026-11-01 确认原话：“按你推荐的来，接受 ADR-0036 到 0045”。按本文“提议的安全调用方式”接受；“仍不能开放的部分”继续排除，也不抵充 4014 完成数。所有候选仍默认关闭，按随产品审阅的精确编译分支逐组开放；逐次审批、scratch 限定与实机验证要求不变。本决定只接受本类别的审阅边界，逐组例外仍须留下批准记录。

## 后续验证与依据

Small 覆盖窗口匹配、拒绝审批代答、回调状态机；Medium 模拟模态、取消晚到、恢复失败；Large 核对选择/活动页恢复、合法回调驱动、主线程卡住及单步撤销，不以 Host 超时冒充 EPLAN 已取消。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
