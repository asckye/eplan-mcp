## 背景与问题

1.0.0 候选包的虚拟机连接要工程师在虚拟机里填三样东西：虚拟机 IPv4、宿主机 IPv4（防火墙只放行它）和一个正在运行的 EPLAN 实例（服务固定对应它）。负责人在虚拟机上试用时认为宿主机地址和 EPLAN 实例都是多余的步骤，并且服务固定对应一个实例时，AI 不能启动、关闭、重启或切换 EPLAN（`eplan_session_start` 等在固定模式下拒绝）。

## 决策

1. **不填宿主机地址**：Workbench 的虚拟机面板只有虚拟机 IPv4 和端口；建立防火墙规则时远程地址为 Windows 的 `LocalSubnet`（本机各网卡所在的子网），仍然只放行当前 `eplanmcp.exe` 的这个 TCP 端口，仍然只在域和专用网络配置文件中生效。命令行 `vm-firewall` 的 `--host-address` 变为可选：给出时照旧只放行该地址。移除规则时不再要求地址与建立时一致，旧版本按宿主机 IPv4 建的规则也能移除。
2. **只给 MCP 地址**：面板显示 `http://<虚拟机 IPv4>:<端口>/mcp`，可选中，可一键复制；客户端只需要这个地址。
3. **不绑定 EPLAN 进程**：`serve --http` 不带 `--process` 时不再要求恰好一个 EPLAN 在运行，也不绑定任何实例；它和本机 stdio 的 Host 一样发现、选择、启动、关闭和重启 EPLAN（关闭、重启仍只在只开着 scratch 项目时进行，ADR-0058）。带 `--process` 时照旧固定对应那个实例。Workbench 不再提供实例选择。
4. **不变的部分**：没有密钥（ADR-0062）；Host 头和 Origin 校验；审批、scratch 规则、破坏性操作两步确认、写入暂停和审计都不因网络连接而放宽；`writesOutsideScratch` 仍默认 `approve`。

## 后果

- 好处：虚拟机连接只剩“选地址、放行、启动、复制地址”四步；AI 在虚拟机里可以自己启动 EPLAN、在多个实例之间切换、关闭或重启 EPLAN。
- 代价与风险：
  - **同一子网里的任何电脑都能连上这个端口并调用工具**，包括读取项目数据（HTTP 明文）和发起写入。写入仍要工程师在虚拟机里审批，但读取不需要。只在你信任的私有网络（例如 VMware/Hyper-V 的仅主机或 NAT 网络）中使用；桥接到办公网络时，子网里的其他电脑同样能访问。
  - 与“关闭普通写入审批”（ADR-0061 的 `allow`）同时使用时，子网里的任何程序都能不经确认地修改 scratch 以外的项目。入门文档继续提醒不要这样组合。
  - 服务不再绑定实例后，同一台虚拟机有多个 EPLAN 时，AI 可能选错实例；按入门文档先确认目标再 `eplan_session_select`。
- 以后要收紧时：改回填宿主机地址（`--host-address` 仍然可用），或者为 HTTP 重新引入认证，都需要新的 ADR。
