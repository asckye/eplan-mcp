# ADR-0043：对授权 API 采用只读优先、隔离占用与凭据禁止边界

| 项 | 内容 |
|---|---|
| 状态 | Proposed |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（待决定） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；未接受前现行规则不变 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **9 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

包括 `License.GetLicenseModules/LockOption/Type/DongleNumber` 和 `EplApplication.License/LicenseFile/Password/User`。这 9 组按首阻列入授权/凭据类别，不表示每组都会占用许可。目录中 `Password`、`User` 仅有 setter，`LicenseFile` 有 getter/setter；不能虚构读取密码的 getter。A2 已验证 `HasOption` 只检查，`LockOption` 会占用直到 EPLAN 退出。

授权可能是团队共享或有到期时间的借用许可；占用会影响其他工程师，不能由 scratch 事务释放。读取授权文件、加密狗标识、用户或密码还可能泄露凭据/个人信息；把“未授权”当安全违规会误导诊断。

## 提议的安全调用方式

1. 先通过专用只读工具返回允许报告的模块名、是否可用、脱敏状态及必要到期提示，遵守 SEC-11；目录能查但禁止返回授权文件内容或凭据。缺失授权只报环境/证据缺口，不判违规，也不绕过厂商检查。
2. 对 Password/User 的 setter，若负责人认为必须调用，只研究由独立人工窗口输入测试凭据、用一次性 secret_ref 绑定该实例和审批的专用适配器；秘密仅在受控内存中短暂传递并清除，不进入模型、参数原文、摘要日志或审计。LicenseFile 仅允许人工授权的合法测试文件引用、不读取内容；DongleNumber 可研究返回存在状态或会话化脱敏值，原号不交模型。此项需要明确批准对 SEC-11 的限定例外，未批准仍不执行。
3. 对确需 LockOption 的调用，提议只在工程师明确提供的合法测试许可和可丢弃测试实例上逐次审批；显示模块、可能影响的共享席位、占用直到退出及释放计划。调用前记录只读状态，结束后退出隔离实例并核验席位释放，不能声称 SafetyPoint 可回滚许可。
4. 长运行批次有占用预算与取消计划；释放不明/网络授权不可观测只报告不确定及证据缺口，暂停后续占用，交人工核验。审批凭据由工程师在厂商窗口输入，模型、工具结果和审计均不接收秘密。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

绕过/伪造/破解许可、复制授权文件、让模型提供或收到密码、返回加密狗原始唯一标识不开放；这不等于已证明每个 getter/setter 都无法通过脱敏专用适配器调用。许可供应商不提供释放保证时，不能承诺“调用后立刻还回”；没有合法许可也无法通过审批创造执行权。

## 备选方案与代价

维持 HasOption/模块检查能满足大部分诊断；开放全部授权对象会泄密并耗席位；隔离实例中的精确模块占用可研究，但需要合法资源和可靠退出验证，不能占用户当前实例。

## 需要项目负责人决定

是否保持模块状态只读优先，秘密字段始终不返回？是否接受由人工提供测试凭据的专用 setter 适配器及脱敏 getter，并明确 SEC-11 的例外范围？是否允许合法测试许可上的 LockOption，接受直到实例退出的占用？谁准备独立许可，席位释放不明时如何人工确认？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。尚未接受，不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 后续验证与依据

Small 验证秘密字段不出结果/审计、未知许可只警告；Medium 验证逐次审批与占用预算；具备明确许可授权后 Large 核对只读查询无占用、LockOption 实例退出后释放及未授权诊断。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
