# ADR-0001：用 ADR 记录架构决策

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-10-12 |
| 决策人 | 项目负责人 |
| 门的类型 | 双向门 |

## 背景与问题
项目初期只有一名开发者加 AI 助手。AI 助手每次会话都不记得之前的讨论，人也会忘。如果决策只存在于聊天记录中，几个月后就没人说得清某个设计为什么是现在这样，结果要么不敢改，要么改出问题。

## 决策
采用 Michael Nygard 提出的架构决策记录（ADR），使用 MADR 格式，存放在 `docs/adr/`，和代码一起评审。哪些变更需要 ADR，按 [开发流程](../process/development-workflow.md#3-变更分级与设计产物) 的 L3 标准判断。

## 后果
- **好的**：决策有出处；新的贡献者（包括新的 AI 会话）可以快速了解"为什么"；推翻决策时必须正面说明理由。
- **代价**：每个 L3 决策需要额外花半小时到一小时写清楚。
- **后续行动**：`CLAUDE.md` 要求 AI 助手在提出 L3 改动前先读相关 ADR。
