# ADR-0028：采用版本化的不可变计划定义和原子状态记录

| 状态 | Accepted |
| 日期 | 2026-10-23（提出）· 2026-10-23（接受：项目负责人选择"接受"） |
| 决策人 | 项目负责人 |
| 门的类型 | 单向门：新增持久化数据格式，按开发流程属于 L3 |

## 背景与问题
ADR-0023 已决定持久化计划及 planHash，但未固定规范序列化、状态替换和清理边界。[开发流程](../process/development-workflow.md)第 3 节将数据落盘格式列为 L3，不能仅凭 L2 实施设计启用。

## 决策驱动因素
审批绑定的定义不可变；执行状态需要原子更新；跨调用不能保存运行时对象标识；记录和备份不能被容量淘汰伪装成“未写入”。

## 备选方案
1. 只用内存计划，退出即丢失。
2. 版本化 definition/state JSON，加内容寻址证据；继续使用现有审计核实中断。
3. 引入数据库并实现持久化任务恢复。

## 决策
采用方案 2；精确 schema、canonical/planHash、state\plans 布局、24 h 可执行期、保留/配额及归属限制见[实施设计 4.1](../design/2026-10-23-m6-phase2-plans.md#41-计划记录与生命周期)。不把落盘当作批准凭据，不自动继续写步骤，不改变单步四值结果或审计链格式。

## 后果
P01–P04 及其下游按本决策实现。首次 schema=1 不迁移既有数据；未知 schema 保留并拒绝执行。Small 验证规范哈希与状态机，Medium 验证原子替换、容量/损坏/并发和中断。阶段 5 的任务恢复不随本 ADR 提前实施。
