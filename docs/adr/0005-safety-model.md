# ADR-0005：安全模型：分级、策略引擎、审批、事务、审计

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-10-12（提出）· 2026-10-13（接受） |
| 决策人 | 项目负责人 |
| 门的类型 | 单向门：之后放宽任何一项默认值，都需要新的 ADR |

## 背景与问题
本系统让 AI 代理修改工程师的真实 EPLAN 项目。模型可能误解意图、传错参数，也可能被项目数据中的文本诱导（提示注入）。MCP 规范明确规定，客户端必须把工具注解视为不可信的提示，所以**安全不能依赖客户端或模型的自觉，必须由服务器在代码中强制执行**。

## 决策

### 1. 每个工具都有一个安全级别

| 级别 | 定义 | 示例 | 默认策略 |
|---|---|---|---|
| **Read** | 不修改项目、主数据和设置 | 列出页面、读取设备、读取检查结果 | 允许 |
| **Write** | 增加或修改项目内容，可以撤销 | 新建页面、放置设备、设置属性 | scratch 项目中自动允许；**真实项目需要审批** |
| **Destructive** | 删除数据，或大范围、难以逐项撤销的修改 | 删除页面、整个项目重编号、覆盖式导入 | **始终需要审批**，执行前自动备份项目 |
| **Code** | 执行任意代码，或做持久化的系统级修改 | 执行 C# 脚本、注册插件或脚本、修改 EPLAN 设置 | **默认禁用**，不在任何默认 Profile 中；即使在配置中启用，每次调用仍然需要审批 |

级别和 MCP 注解一一对应（Read → `readOnlyHint: true`；Destructive → `destructiveHint: true`），由 CI 检查二者一致。

### 2. 策略引擎
- 在 Host 中实现为**纯函数**：输入为（级别、目标项目、是否在 scratch 根目录中、配置），输出为（允许 / 需要审批 / 拒绝，并附原因）。
- 写类工具**必须显式指定目标项目**，不允许隐式使用"当前项目"。
- 项目是否在 scratch 中，按规范化后的完整路径判断（解析符号链接、`..`、短文件名），防止路径绕过。
- 安全相关的配置只能通过配置文件修改，**没有任何 MCP 工具可以修改它们**。

### 3. 审批
- 先 dry-run 生成变更清单，再请求审批，**审批针对的是具体的变更清单**，不是笼统的"允许写入"。
- 渠道按优先级：
  1. MCP elicitation：2026-07-28 规范下通过多轮请求完成；
  2. EPLAN 内的审批对话框；
  3. 都不可用时拒绝。
- 交给客户端往返的 `requestState` 经 HMAC 签名并设置有效期（默认 5 分钟），只引用保存在 Host 中的计划，防止被篡改或重放。
- 执行时比对项目状态指纹。审批后项目发生了变化的，返回 `PLAN_STALE`。
- 拒绝、取消、超时都视为"不执行"，项目保持原样。

### 4. 事务与撤销
每个写操作都在 Bridge 的固定包装中执行：`LockingStep` → `UndoStep` → `SafetyPoint` → `QuietModeStep`。失败时回滚；成功后整个操作在 EPLAN 中只占一个撤销步骤；不会清空工程师自己的撤销历史。Destructive 操作执行前，按策略先备份项目。

### 5. 审计
- 每次调用一条 JSONL 记录，带哈希链，`eplanmcp audit verify` 可以校验。
- **审计不可写时，写操作一律拒绝执行。**

### 6. scratch 沙箱
默认的 scratch 根目录是 `%LOCALAPPDATA%\EplanMcp\scratch\`。`eplan_scratch_create` 把项目复制或备份还原到这里，供 AI 自由试验；试验满意后，由工程师自己决定是否在真实项目上重做（或者走审批）。

## 修订（2026-10-13，依据 spike S2）
决策本身不变，只更正第 4 节中的嵌套顺序：实测表明，`UndoStep` 放在 `SafetyPoint` 外面时，`SafetyPoint` 的回滚会静默失效。正确的顺序是 `LockingStep` → `SafetyPoint` → `UndoStep`（在 SafetyPoint 内创建）→ `QuietModeStep`，成功时先 `Commit()` 再 `CloseUndo()`。按这个顺序，失败时可以回滚，Ctrl+Z 可以一次撤销 AI 的操作，而且工程师原有的撤销历史保持完整。详见 [spike S2](../../spikes/S2-transactions/README.md)。上述结论是在插件 action 中测得的，在主线程调度器中的行为由 spike S1 复核。

另：默认的 scratch 根目录已由 [ADR-0008](0008-data-locations-and-instance-discovery.md) 改为 `%USERPROFILE%\EplanMcp\scratch\`（2026-10-13）。

## 修订（2026-10-13，Workbench 审批渠道）
项目负责人决定借鉴 TIA 项目的 Workbench 图形界面（M5）。审批渠道相应增加一种，优先级为：MCP elicitation → **Workbench 审批队列**（Workbench 正在运行时）→ EPLAN 内的审批对话框 → 拒绝。第 3 节的其他规则不变：审批针对具体的变更清单，`requestState` 签名并设有效期，执行前比对项目状态指纹。

## 修订（2026-10-20，ADR-0010：写操作的结果与恢复）
[ADR-0010](0010-write-outcomes.md) 补充第 3、4 节：
- 写工具的结果和错误都带执行状态 `execution`（`not_started`、`rolled_back`、`committed`、`unknown`）。
- 中断后 Host 先向 Bridge 查询结果（`outcome.get`），**从不自动重发写操作**。
- 无法确定时返回 `OUTCOME_UNKNOWN`，并暂停目标项目和当时那个 EPLAN 实例的写入，工程师经审批渠道确认后才解除。

其余规则不变。

## 修订（2026-10-20，ADR-0011：审批只经独立窗口）
[ADR-0011](0011-approval-out-of-band.md) 取代第 3 节及 2026-10-13 修订中的渠道顺序。审批只经工程师独立操作的窗口，顺序为：
1. Workbench 审批队列（M5，Workbench 正在运行时）；
2. EPLAN 内的审批对话框；
3. 都不可用时拒绝。

MCP elicitation 不再用于审批，也不用于解除写入暂停，因为表单由 AI 客户端自己显示、自己回答。交给客户端往返的 `requestState` 随之不再需要。审批请求 ID 由 Host 生成，决定绑定请求 ID、计划指纹和参数摘要，只能使用一次。期限默认 120 秒，可在 `config.json` 中设为 60–300 秒。

第 3 节的其他规则不变：审批针对具体的变更清单，执行前比对项目状态指纹，拒绝、取消、超时都不执行。

## 后果
- **好的**：模型出错或被诱导时，伤害被限制在 scratch 中，或者被审批拦下；所有修改都可以追溯、撤销。
- **代价**：真实项目上的每次写入都要人工点一次确认，自动化程度受限。这是有意的取舍；之后如果要增加"会话内对同类操作免审批"等便利措施，必须另写 ADR。
- **后续行动**：
  - 策略引擎的决策表 100% 由 Small 测试覆盖；
  - 质量场景 Q1、Q2、Q3、Q6、Q7、Q9 写成自动化测试；
  - 威胁模型见 [security.md](../standards/security.md)。
