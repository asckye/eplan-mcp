## 背景与问题

2026-11-01 的项目回顾检查了 Workbench 界面和 [workbench-ui.md](../standards/workbench-ui.md)：颜色已经全部走主题变量，但间距、尺寸写死在各个视图里，宽度固定，等宽字体下英文容易截断，错误只用红字表示。项目负责人决定先出设计稿，v0.5.0 之后再实现，并提出"UI 的设计我觉得可以参考 Apple"。设计稿按这个方向完成后，项目负责人同意按推荐方案推进。

随后项目负责人提供了自己完成的 v2 设计导出（HTML、PNG 与 `tokens.json`），以它为准。ADR-0017 写的是"学规范，视觉也和 TIA 一致"。改走 Apple 方向，就必须修订这一条，所以另写本 ADR。

## 决策（提议）

1. **技术栈不变**：WPF（.NET 10）、`ThemeManager`、浅色/深色/高对比三套调色板、ADR-0017 引入的 Primer 主题文件都保留。新视觉放在项目自己的资源字典里，不改 vendored 区域（`VendoredThemeTests` 继续有效）。
2. **视觉语言参考 Apple 人机界面指南的原则**，不复制 Apple 的界面、图标或字体：
   - 页面用大标题（28 px，粗体），不再用面包屑；
   - 信息用分组圆角列表：标签在左、值在右，行间用细分隔线；
   - 切换用分段控件；
   - 只用一个强调色（文字可用的系统蓝，例如 `#0A64D2`，在白底上对比度不低于 4.5:1）；状态色只表示状态；
   - 圆角 8/10/12 px；靠留白和细边框分层，不用渐变和重阴影；
   - 状态一律"图标 + 文字"，不只靠颜色。
3. **字体**：界面文字用 Windows 系统字体（Segoe UI Variable，回退 Segoe UI；中文 Microsoft YaHei UI）；标识符、路径、代码类文字用 Cascadia Mono，回退 Consolas。不再随软件分发 Maple Mono CN。不使用 SF 字体和 SF Symbols（授权不允许）；图标自绘。
4. **不做的**：WPF 没有 macOS 那样的毛玻璃，侧边栏用纯色近似；不加动画效果，系统设置要求减少动态效果时也不出现动画。
5. **审批公平不变**：批准和拒绝两个按钮外观完全一样、位置固定、没有默认按钮（ADR-0014）。
6. **实现方式**：先合入变量准备（间距、图标尺寸、语义颜色别名，分支 `feat/workbench-tokens`）；再增加生成器，从设计规范的 `tokens.json` 生成三套调色板和尺寸变量，设计变更只改这一个文件；最后改项目自己的控件样式和页面布局。v2 中改变审批行为的部分（破坏性操作默认拒绝与输入确认）不在本 ADR 范围，见 [ADR-0035](0035-destructive-approval-default-reject.md)；"在 EPLAN 中定位"需要新的进程通信能力，这一版不做。workbench-ui.md 中颜色、字体、圆角、间距的规则同步修订；"与 TIA 同步"的条款只保留可访问性和审批规则，不再要求视觉同步。
7. **时间**：v0.5.0 发布之后实现；在此之前只合入不改变外观的变量准备。

## 备选方案

- **维持 TIA 视觉，只修问题**（间距、截断、错误图标、高对比映射）：工作量最小，但不符合项目负责人的新方向。
- **改用 WPF 的 Fluent 主题或第三方界面库**：要换掉现有主题引擎和测试，工作量大，也不是 Apple 风格。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 视觉变化大，用户需要重新熟悉 | 页面结构和快捷键不变（Ctrl+1–4、F5 等），只换外观 |
| 对比度或高对比主题回退 | 沿用 `ThemeContrastTests`，新增别名在三套调色板中都必须存在 |
| 与 TIA 的主题合并路径不再适用于视觉部分 | 新样式放在项目自己的字典里，vendored 文件不改，仍可单独同步 TIA 的修复 |

## 决定

2026-11-01 项目负责人接受：v0.5.0 之后按 v2 设计实现，并修订 workbench-ui.md。
