# ADR-0046：对绘图写入后的非安全读回偏差采用提交加警告，不再整体撤销

## 背景与问题
绘图写工具（`eplan_connection_create`、`eplan_device_place`、`eplan_placement_create/update/edit`、`eplan_macro_insert`、`eplan_import_dxf`）在提交后读回实际结果，与规划比较。现在任何不一致都会让 `TransactionRunner` 撤销本次全部改动，返回 `rolled_back`。

客户页重绘（2026-10-30 至 11-02）中，大部分撤销来自预测与实际的细小差别，而不是错误写入：
- 带偏移引脚的 T 节点变体，自动连接线的预测起点与实际引脚差 2 mm；
- 移动电缆时 EPLAN 新建未命名定义点及其文字（A73）；
- 实测外框与符号库外框不同，写后布局检查判为线穿外框或重叠；
- 默认文字位置与其他对象冲突。

每次撤销都要再改代码、再跑一轮实机，代理也只能盲目重试。负责人 2026-11-02 的方向是先把主要功能做完整，不做拖累项目的防御性检查。

## 决策驱动因素
- 数据完整性第一：不能改动计划以外的对象，不能把不同的电气网络连在一起，不能留下无法描述的结果。
- 对代理友好：一次已提交的写入加上精确的偏差事实和修复建议，比撤销后从头再来更有用；`eplan_page_review` 的审查—修复循环已能处理布局类问题。
- 写入仍是一个撤销步骤，工程师在 EPLAN 中一次撤销即可恢复。

## 备选方案
1. 维持现状：任何读回不一致都整体撤销。
2. **分类处理**：与安全有关的不一致仍撤销；其余提交，以结构化警告返回。
3. 一律提交加警告，只有异常和事务失败才撤销。
4. 方案 2 加调用参数 `strict_readback`，由调用方选择恢复整体撤销。

## 决策
选择 **方案 2**。

### 1. 仍然整体撤销的情况（安全类，封闭列表）
| 编号 | 情况 | 例子 |
|---|---|---|
| S1 | 改动了计划以外的既有对象 | 删除或修改了不在规划或移动闭包中的对象；既有对象丢失属性或芯线分配且规划未声明 |
| S2 | 新对象落在页面以外 | 对象位于 Page.Size 之外（2026-10-30 验收试运行中 PLC 点落在原点） |
| S3 | 生成后把不同网络连在一起，或断开了计划外的既有连接 | 逻辑连接把两个原本独立的网络合并 |
| S4 | 读回找不到本次创建的对象 | 无法向调用方说明写入了什么 |

### 2. 提交并警告的情况（偏差类）
范围仅限本次规划内的对象，并且不属于第 1 节：
- 写后布局规则 R1–R9 的违规（重叠、线穿外框、文字冲突、栅格），对象仍在页面内；
- 自动连接线的形状或端点与预测不同，但仍在同一网络内；
- 同一网络内逻辑配对的顺序不同（例如链式与星形）；
- 位置、外框、文字位置与预测不同；
- 显示类属性（芯线标签与颜色、交叉引用显示文本）与预测不同；
- 外框无法测量：记为“未验证”警告，不再拒绝。

结果为 `execution: committed`，`warning` 中写一行摘要，`metadata.readbackDeviations` 中逐条给出：类别、对象定位器、预测值、实际值和建议的修复工具（通常是 `eplan_page_review`、`eplan_placement_update` 或 `eplan_connection_create`）。审计记录同样写入这些偏差。

### 3. 不变的部分
- 写前检查（参数、策略、审批、写前布局规则）照旧拒绝，`not_started`。
- 事务中的异常照旧回滚，`rolled_back`；结果无法确定照旧 `OUTCOME_UNKNOWN` 并暂停写入。
- ADR-0010 的两条不变式不变：`committed` 不可重试。

## 后果
- **好的**：客户页重绘不再因 2 mm、默认文字位置之类的差别反复撤销；代理拿到偏差事实后可以直接修复；实机轮次减少。
- **坏的或要付出的代价**：项目中可能留下与预测不同的结果，需要代理或工程师根据警告修复；调用方不能再把 `committed` 理解为“与预测完全一致”。
- **后续行动**（接受后）：
  1. 在 `TransactionRunner` 的提交后校验中区分两类：安全类照旧抛出，偏差类收集为警告；
  2. 各绘图工具把现有不一致检查归入第 1 节或第 2 节，规格中写明；
  3. Small 测试覆盖每个安全类仍撤销、每个偏差类提交并带警告；
  4. 更新 mcp-tool-design 的错误与警告说明，以及工具规格中“读回不符整体补偿”的描述。

## 各方案利弊
### 方案 1
- 优点：`committed` 等于完全符合预测。
- 缺点：预测不可能覆盖 EPLAN 的全部细节，撤销次数多，主线进度慢。

### 方案 3
- 优点：实现最简单。
- 缺点：越界改动和跨网连接也会留在项目里，违背数据完整性。

### 方案 4
- 优点：保留严格模式。
- 缺点：多一个参数和两套行为要测试；目前没有需要严格模式的调用方，需要时再加。
