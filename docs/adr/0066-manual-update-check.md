# ADR-0066：Workbench 只在工程师点击时检查更新，只读版本号，不下载

## 背景与问题

安装验收清单 I5 承诺“安装和使用都不需要联网”。Workbench 至今不发起任何网络请求（虚拟机连接只在宿主机和虚拟机的私有网络之间，且由工程师配置）。2026-11-20 的设计稿在“关于”卡片上放了“检查更新”按钮，点击后显示是否有新版本。

## 备选方案

1. 去掉按钮，只显示当前版本。
2. 按钮只在浏览器里打开 GitHub Releases 页面，Workbench 自己不联网。
3. **按钮点击时由 Workbench 请求一次 GitHub 的最新版本信息，只比较版本号**（本提议，负责人 2026-11-20 选择）。
4. 启动时自动检查、自动下载。

## 决策（提议）

采用方案 3，限制如下：

1. **只在点击时联网**：启动、定时、后台都不检查；没有“自动检查”开关。
2. **只读版本号**：请求 `https://api.github.com/repos/asckye/eplan-mcp/releases?per_page=10`（含预览版），只取标签名和发布页链接；不发送任何本机信息（请求头只有固定的 `User-Agent: EplanMcp-Workbench/<版本>`，不带项目、用户或机器标识）。超时 10 秒。
3. **不下载、不安装**：有新版本时显示版本号和“打开发布页”按钮，在浏览器里打开；升级仍按发布说明手动替换程序目录（ADR-0016 的 ZIP 修订）。
4. **失败照常可用**：断网、被代理拦截、GitHub 限流时只显示“无法检查更新”和原因，不影响其他功能。
5. **I5 改为**：“安装和使用都不需要联网；只有工程师点击‘检查更新’时才访问 GitHub，只读版本号。”

## 后果

- 好处：工程师能看到有没有新版本，不必自己去翻发布页。
- 代价：多一个对外请求；离线环境下这个按钮总是失败（已说明）。
- 风险：GitHub 返回的内容是外部数据，标签名和链接要校验格式（标签须匹配 `^v\d+\.\d+\.\d+$`，链接须以 `https://github.com/asckye/eplan-mcp/releases/` 开头），不符就当作“无法检查”。
