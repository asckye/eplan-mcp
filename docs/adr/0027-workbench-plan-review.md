# ADR-0027：扩展 Workbench 的计划审阅与计划结果通知（提议）

| 项 | 内容 |
|---|---|
| 状态 | Proposed |
| 日期 | 2026-10-23 |
| 决策人 | 项目负责人（待确认） |
| 门的类型 | 单向门：改变严格解析的 Workbench IPC 合同 |

## 背景与问题
ADR-0023 要求完整计划审阅；当前 ApprovalAskParams 只有纯文本 Changes 等字段，界面最多 200 行/每行 400 字符。WriteExecution 只有四值，不能表示 partially_committed；当前 WorkbenchChannel 把未知值映为 Unknown，不能用于计划结果。

## 决策驱动因素
保留独立窗口、精确绑定、期限、一次性和送达后不切换渠道；不能把确定的部分完成显示为未知，也不能假称摘要是完整差异。

## 备选方案
1. 继续使用 v1 的摘要、完整清单路径，结果通过 plan_get 查询。
2. 后续扩展版本化协议，携带结构化计划审阅内容，并为计划结果增加第五值。

## 提议决策
提议方案 2 作为后续独立工作；具体字段、版本协商/旧版回退和界面合同须另行评审，不能向 v1 发送未知成员或枚举。未经负责人明确接受，本 ADR 不授权实施。

## 后果
M6 阶段 2 使用方案 1，详见[实施设计](../design/2026-10-23-m6-phase2-plans.md)第 5 节，不依赖本提议。未来实现须有严格解析、N/N-1 兼容、完整审阅及结果显示的 Small/Medium 测试；不放宽任何审批权限。
