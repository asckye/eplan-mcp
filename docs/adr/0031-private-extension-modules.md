# ADR-0031：私有扩展模块以 Host 外的工作进程加载，只能经现有 Bridge 操作和审批流水线写入，默认关闭

| 项 | 内容 |
|---|---|
| 状态 | Proposed |
| 日期 | 2026-10-30 |
| 决策人 | 项目负责人 |
| 门的类型 | 单向门：扩展契约发布后，公司内部模块会依赖它 |
| 影响 | 在 [ADR-0025](0025-code-plugin-worker.md)（算法插件只返回计划草稿）之外，允许扩展模块直接提供 MCP 工具；涉及 [ADR-0005](0005-safety-model.md) 的审批模型 |
| 相关依据 | [M10 设计](../design/2026-10-30-m10-capability-expansion.md) |

## 背景与问题

项目负责人 2026-10-30 要求吸收同类项目的私有扩展机制：公司自己的工具（内部工作流、插件测试工具）不能放进公开仓库，但希望在 EplanMcp 中作为工具出现。ADR-0025 的算法插件只能"数据进、计划草稿出"，不能作为独立工具。

## 决策驱动因素
- 扩展代码不受本项目审查，按不可信代码处理（ADR-0024、security.md）；
- 写入 EPLAN 必须经过审批、审计、事务和撤销（ADR-0005、ADR-0010）；
- stdio 模式 stdout 只给协议（CLAUDE.md 硬性规则 5）。

## 备选方案
1. 不支持扩展，公司工具只能写成 ADR-0025 的算法插件。
2. Host 进程内加载扩展程序集。
3. **扩展在单独的工作进程中运行**（复用 ADR-0025 的工作进程机制），通过声明式清单注册工具；扩展只能调用 Host 提供的已有操作（读工具、计划提交、已验证 action），不能直接访问 Bridge 管道或 EPLAN。

## 决策
选择方案 3。
- **注册**：`config.json` 列出扩展目录及每个扩展的 SHA-256；清单声明工具名（统一前缀，例如 `ext_<公司>_*`）、描述、输入 schema、级别。哈希不符或清单无效则不加载，并在 `doctor` 中报告。
- **运行**：每次调用在工作进程中执行，有时限和输出大小上限；崩溃或超时不影响 Host。
- **能力**：扩展只能通过受控接口调用读工具、提交计划（走 ADR-0023 的一次审批和备份）和 A 级 action；没有直接写入能力，没有 C 级 action。
- **级别与审批**：工具级别取清单声明与其实际调用中最高者；Write 及以上按现有规则审批，审批界面标明"来自扩展 X"。
- **默认关闭**；工具只出现在 full Profile。

## 后果
- **好的**：公司私有工具可以接入，而写入仍受现有安全模型约束。
- **坏的或要付出的代价**：扩展能力受限于 Host 开放的接口；需要维护扩展清单格式和工作进程协议。
- **后续行动**：清单 schema 与契约快照；`doctor` 检查；Medium 测试覆盖哈希不符、超时、越权调用被拒。
