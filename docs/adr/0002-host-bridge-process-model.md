# ADR-0002：采用"进程外 Host + EPLAN 进程内 Bridge"的进程模型

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-10-12（提出）· 2026-10-13（接受） |
| 决策人 | 项目负责人 |
| 门的类型 | 单向门：后续所有代码都建立在这个拆分之上 |

## 背景与问题
MCP 服务器需要读写 EPLAN 项目。EPLAN API 有几个硬约束（[api-notes](../eplan/api-notes.md) B1、B6、B7）：
- 只能在 x64、.NET Framework 4.8.1 的进程内使用；
- 只能在 EPLAN 主线程上调用；
- 修改项目时如果没有创建 `UndoStep`，会清空撤销历史。

MCP 服务器本身则希望使用现代 .NET 和官方 C# SDK，并且通过 stdio 由客户端启动。

## 决策驱动因素
- 工程师要能**实时看到** AI 在 EPLAN 中做了什么，并且能用 Ctrl+Z 撤销；
- 数据完整性：需要事务、回滚、细粒度的错误；
- 可测试性：安全逻辑要能在没有 EPLAN 的情况下测试；
- 失败要可见：实机验证表明，Remote Client 调用脚本时，编译失败也会返回成功。

## 备选方案
1. **Remote Client + 动态生成 C# 脚本**（covagashi/eplan-rag-mcp 的做法）
2. **Remote Client + 插件注册的自定义 Action**
3. **离线程序**：在自己的进程中用 `EplApplication` 无界面运行 EPLAN
4. **进程外 Host + EPLAN 进程内的 Bridge 插件，两者通过自有 IPC 通信**

## 决策
选择**方案 4**。

- **Host**（`eplanmcp.exe`，.NET 10）：负责 MCP 协议、工具、策略、审批、审计。由 MCP 客户端通过 stdio 启动，不引用任何 EPLAN 程序集。
- **Bridge**（net481 插件，`IEplAddIn`，`bLoadOnStart = true`）：在 `OnInitGui` 中取得主线程调度器并启动管道服务器。所有 EPLAN API 调用都通过 `EplanMainThreadDispatcher` 在主线程上执行，并带有等待超时。

方案 2 作为 R1（主线程调度不可靠）的**后备方案**保留。方案 3 作为**第二种 Bridge 宿主**，用于无界面的批处理和 CI（M5），与插件共用同一套代码。

## 后果
- **好的**：
  - 工程师在 EPLAN 界面中实时看到修改，撤销历史完整；
  - Host 可以使用 .NET 10 和官方 SDK，Bridge 只做薄薄的一层；
  - 安全逻辑全部在 Host 中，可以用 Small 测试穷尽验证；
  - 没有"编译失败却报告成功"的问题，错误能精确地传回。
- **代价**：
  - 需要安装和注册插件，安装过程多了一步；
  - 需要自己实现并维护一个 IPC 协议（见 ADR-0003）；
  - 插件运行在 EPLAN 进程中，Bridge 的缺陷可能影响 EPLAN 的稳定性，因此 Bridge 必须保持精简、无第三方依赖，并捕获所有异常。
  - 编译插件受 API 授权方式的约束（开发者授权或运行时授权，见 R0 / ADR-0007）。方案 1 的脚本路线同样需要 API 扩展授权才能访问 DataModel，所以这一点不是选择方案 4 带来的新代价。
- **后续行动**：
  - M1 spike S1：验证 `EplanMainThreadDispatcher` 在插件中是否已就绪、带超时的调度是否可靠、模态对话框打开时的行为；
  - M1 spike S0：验证未签名插件在当前授权下的加载情况与页数限制。

## 各方案利弊
### 方案 1：Remote Client + 动态脚本
- 优点：不需要安装插件；已有开源实现可以参考。
- 缺点：每次调用都要编译；失败不可见；结果通过临时文件传递；依赖 TEMP 等环境；难以做事务。
### 方案 2：Remote Client + 自定义 Action
- 优点：由 EPLAN 负责调度到主线程，并且只在空闲时执行，天然避免和工程师的操作冲突。
- 缺点：参数只能是字符串；只有同步模式才有返回值；没有进度和取消；不加密的旧版 gRPC 客户端还依赖 Bin 中没有的 `System.Memory`，.NET 10 的 Host 需要再加一个 net481 中间进程。
### 方案 3：离线程序
- 优点：完全由自己控制进程；适合 CI。
- 缺点：工程师看不到实时变化；额外占用授权；启动慢；不能显示界面。
