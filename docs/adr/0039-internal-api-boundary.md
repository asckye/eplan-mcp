# ADR-0039：对 internal 签名先审阅公开契约，禁止反射和裸指针绕过

| 项 | 内容 |
|---|---|
| 状态 | Proposed |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（待决定） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；未接受前现行规则不变 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **0 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

本类在 4014 缺口内首阻为 0；`DrawingService.DrawDisplayList(HWND__*, Rectangle)` 是分母内混合组中的 1 条 internal 签名。另有 147 个整组 internal 已在分母外，包括 `Project.getProjectHandle(ProjectHandle*)`、`Context.CreateContextfromInternal(EContext*)`。这些不能静默加回 4014。

目录可见不代表厂商支持调用。internal/native 接口可能依赖未公开布局、借用对象寿命或线程状态，升级后失效或直接使 EPLAN 崩溃；伪造指针还可能访问真实项目或任意内存。ADR-0033 保存受管对象，不提供原生地址安全保证。

## 提议的安全调用方式

1. 先向官方文档/支持核对每个精确签名的公开可用性、版本、线程、所有权和释放规则；存在受支持公开重载时优先使用该重载。名称带 Internal 但目录并未排除者也要核对真实访问级别，不能凭名字判定违规。
2. 仅对有明确厂商契约且能编译直接调用的签名研究最小适配器，限制目标 scratch，逐次审批显示“内部接口、版本限制及崩溃风险”，备份并前后快照；读操作先行，未知或进程崩溃按 ADR-0010 处理。接受本 ADR 不等于任何一个 internal 签名已获准。
3. 若官方支持的接口只暴露原生指针，必须另审 Bridge 私有受管租约/所有者/失效与释放设计；模型只看到不可猜测的令牌，不能看到或提交地址。没有契约时保留证据缺口，不生成调用代码，也不伪称具有永久不可调用证明。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

非公开且没有受支持公开入口的成员，无法在当前编译分发表内合法直接调用；不采用私有反射、改访问权限、猜测 native 布局或模型地址。仅换成公开等价功能不能把原组标可达；未来厂商提供支持契约/SDK 时再复审。

## 备选方案与代价

全排除保持兼容性但不能回答全部目标；任意反射/native 桥覆盖表面更大但无法约束内存和版本；公开重载与逐签名厂商契约成本较高，但有可审查依据。

## 需要项目负责人决定

是否只研究厂商确认可用的 internal 签名，并维持无契约者不执行？原生租约是否值得单独设计？若 4014 中最终出现无合法入口的组，是否要求厂商支持/更换 SDK，而非用目录排除抵充完成？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。尚未接受，不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 后续验证与依据

离线检查精确公开访问与编译；Small/Medium 验证令牌来源、过期、错实例及目标越界；具备支持契约后才安排隔离 scratch Large、失效/崩溃恢复与各支持版本回归。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
