# ADR-0049：写入工具默认只预览（`dry_run` 缺省为 true），执行须显式 `dry_run: false`

|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-03 |
| 决策人 | 项目负责人（2026-11-03："默认预览按手册改"） |
| 门的类型 | 单向门：对外契约的含义改变，客户端与提示词依赖缺省值 |

## 背景与问题
负责人 2026-11-03 决定全部采用《工程开发手册》v1.1。手册 MCP-23（MUST）要求写入工具默认预览：预览不写目标、文件或设备，不等待审批，返回变更清单和计划哈希。
本项目所有写入工具都支持 `dry_run`，但缺省为 false：省略时直接请求审批并执行。合规审计（2026-11-03）把这一点列为"不符合"。

改缺省值改变了已发布工具的含义（手册 MIG-01、MIG-02、P-25），需要按版本政策处理。

## 决策驱动因素
- 安全：模型漏写参数时只得到预览，不会弹出审批或改动项目（MCP-23 的理由：预览路径写入会绕过审批）。
- 兼容：现有客户端、提示词和评测任务依赖"省略即执行"。
- 一致：plan/execute、指纹和审批流程不变，只改缺省值。

## 备选方案
1. 维持缺省 false，写一份例外 ADR，理由是审批对话框本身就是预览。
2. **按手册把缺省改为 true；执行须显式 `dry_run: false`；在 0.5.0 中改，发布说明附新旧对照表，按工具组分批迁移。**
3. 新增一个 `execute` 参数并弃用 `dry_run`。

## 决策
选择方案 2。
- 所有写入、破坏性和本地数据写入工具（以契约快照中带 `dry_run` 的工具为准）缺省 `dry_run: true`。省略时返回预览：变更清单、计划指纹，`execution: not_started`，不请求审批，不修改项目或文件。
- 要执行，调用方传 `dry_run: false`；审批、事务、读回、撤销与审计的流程不变。预览结果的提示（`hint`）写明"再次调用并传 `dry_run: false` 以执行"。
- 版本：在 0.5.0 改变（1.0 之前，次版本承载破坏性变化）；CHANGELOG 与发布说明附逐工具的新旧对照表（MIG-02），工具说明、usage、示例、评测任务同步更新。
- 迁移按工具组分批落地，每批一个变更集（≤200 行生产代码加文档），每批更新契约快照，并测试省略、true、false 三条路径。
- `eplan_plan_apply` 等以计划为输入的执行工具：计划本身已经是预览结果，保持现有语义，在对照表中写明。

## 后果
- **好的**：符合 MCP-23；模型误调用不会产生审批弹窗或写入；预览与执行的边界清楚。
- **坏的或要付出的代价**：每次写入多一次调用（先预览再执行）；现有提示词和评测需要更新；迁移期间不同工具组的缺省值暂时不一致，发布说明中列出。
- **后续行动**：按工具组的迁移变更集；评测任务更新；发布说明的对照表；`docs/standards/README.md` 声明中无需另写例外。

## 各方案利弊
### 方案 1
- 优点：不改契约。
- 缺点：仍不符合 MUST；模型漏参数即触发审批，依赖人每次拒绝。
### 方案 3
- 优点：参数名语义更直接。
- 缺点：所有工具多一个参数，旧参数弃用期长；收益不比方案 2 大。
