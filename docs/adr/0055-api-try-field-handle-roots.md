# ADR-0055：`eplan_api_try` 把公开字段也当作句柄来源

| 项 | 内容 |
|---|---|
| 状态 | Proposed（等项目负责人确认） |
| 日期 | 2026-11-14（提出） |
| 决策人 | 项目负责人 |

| 影响 | 扩展 [ADR-0033](0033-api-try-object-handles.md) 的句柄来源范围；涉及 [ADR-0005](0005-safety-model.md) 的审批内容与安全面，按 CLAUDE.md 硬性规则 3 只提议 |
| 相关依据 | [结案清单](../design/2026-11-14-api-closeout-list.md) 第 3 节、生成的 `catalog/api-try-handle-reachability.g.tsv` |

## 背景与问题

2026-11-14 重算的覆盖报告：操作层 4014 组里到不了 1009 组（25.1%），其中 `declaring_type_unreachable` 687 条——拿不到那个类型的句柄，它的成员就全都调不到。

这些类型里有一类的来源很明确，却正好落在现有规则之外：**公开字段**。生成的可达性表把它们记作 `[type-layer field; outside operation dispatch]`：

| 类型 | 到不了的组数 | 唯一来源 |
|---|---:|---|
| `Graphics.PlaceHolder.VariablesClass` | 11 | `F:Eplan.EplApi.DataModel.Graphics.PlaceHolder.Variables` |
| `Graphics.PlaceHolder.ValueSetsClass` | 11 | 同上的 `ValueSets` |
| `Graphics.PlaceHolder.Variable` | 3 | 经 `VariablesClass.Item(...)`，而 `VariablesClass` 本身到不了 |

ADR-0033 的句柄来源是**方法返回值和属性 getter**；字段不在操作层分发范围内（字段按覆盖口径只作为依赖计数，不算覆盖率）。结果是占位符的变量与值集读不到——而参数化模块（M6 第 3 阶段）正是建立在占位符的变量和值集上，`eplan_placeholder_list` / `eplan_placeholder_apply` 现在只能读到工具自己封装的那部分。

## 决策驱动因素

- EPLAN API 必须在主线程调用；句柄只在一次调用的生命周期内有效（ADR-0033 已定）。
- 字段读取本身没有副作用，但字段**可写**：允许写字段等于绕过属性 setter 的全部校验。
- 覆盖口径里字段不算分母；本 ADR 不改口径，只让字段成为**到达其他组的路径**。
- 不能为了把"到不了"的数字做小而扩大安全面（负责人 2026-11-02「不做无意义的实验」、11-01「不靠试错」）。

## 备选方案

1. **只读公开实例字段可以作为句柄来源**：生成器把"公开、非静态、类型在目录内、所属类型已可达"的字段，按属性 getter 的同一套接收者与排除规则，生成为取句柄的分支；只生成读取，不生成任何字段赋值。
2. **静态字段也允许**：顺带覆盖类型层的全局对象。
3. **不动生成器，为占位符的变量与值集写专用工具**：扩展 `eplan_placeholder_list` 的返回，把变量与值集的成员直接做成工具字段。
4. **保持现状，把这 25 组结案为"明确不做"**。

## 决策

选方案 1。

- 只有**实例**字段，且所属类型本身已有已批准的句柄路径（深度仍受 ADR-0033 的 4 层限制）。
- 只生成**读取**：字段赋值一律排除，理由记为 `field_write`。
- 接收者、参数、返回类型沿用属性 getter 现有的全部规则与排除表（ADR-0036–0045 的分类不变）。
- 审批内容照 ADR-0033 显示句柄来源，并标明它来自字段。
- 黄金测试先行：生成清单（`catalog/api-try.g.tsv`）与可达性表的差异在实现前作为快照固定，只允许新增这三类字段带来的条目。

不选方案 2：静态字段是进程级的全局对象（如 `Base.Settings` 这类），与 scratch 边界无关，风险和收益都不在本 ADR 的范围。
不选方案 3：占位符只是第一个例子，字段作为来源是通用缺口，逐个写工具会重复 ADR-0032 否决过的"每组一个工具"。
不选方案 4：参数化模块需要这些成员，结案等于把 M6 第 3 阶段的能力划掉。

## 后果

- **好的**：占位符的变量与值集可读，参数化模块的数据能被代理看见；"到不了"减少 25 组，且是真能力增加，不是补理由。
- **坏的或要付出的代价**：api_try 的生成分支增加，审批文本要多一种来源说明；字段读取的返回对象仍是短期句柄，调用结束即失效，代理必须在同一次调用里用完。
- **后续行动**：生成器改动 + 黄金测试；`eplan_api_try` 工具规格补写字段来源；实现后在 scratch 上实机读一次占位符的变量与值集，结论写入 api-notes；覆盖报告重算。
