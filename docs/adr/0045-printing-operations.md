# ADR-0045：对打印调用采用虚拟队列优先与物理输出逐次确认

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（2026-11-01 接受） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；接受后按本文边界逐组实施 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **2 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

包括 `HEServices.Print.Pages` 和 `Print.Project` 两组。打印机参数或默认设备可能指向本机、网络队列或虚拟驱动，不能由 scratch 项目判断输出目的地。

物理打印消耗纸张/耗材、在共享设备上泄露项目内容；网络打印可能传出数据。虚拟驱动也可能弹出保存对话框或写入任意位置，阻塞 EPLAN 主线程。作业提交后取消不保证未出纸，项目事务不能撤回。

## 提议的安全调用方式

1. 先研究固定测试虚拟打印机/受控队列，限定目标 scratch、页范围、份数与输出路径；驱动能无对话框写新建 exports 并校验产物时，才开放对应精确签名。保存窗口取消采用 ADR-0037，不接受任意驱动或默认打印机隐式回退。
2. 物理打印作为单独可选阶段，工程师预先登记精确队列；逐次审批展示“物理打印不可撤回”、设备位置/队列、页清单、份数、估计总页数及共享设备影响。网络设备另满足 ADR-0044，队列变化使计划过期。
3. 提交后记录作业 ID（API/驱动可观测时）、队列状态和发送结果；超时按未知结果，不自动重印。尽力取消仅是恢复措施，须如实报告已出纸或无法确认；快照证明输入一致，不能证明物理作业未发生。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

已经出纸或被远端接收的内容无法回滚。没有无交互能力的驱动不能承诺整夜无人值守；作业 ID/状态缺失只报告证据缺口，不伪装违规或成功。无限份数、隐式默认队列、未知目的地及真实客户项目不开放。

## 备选方案与代价

现有 PDF 导出后人工打印最容易审查；测试虚拟打印机能先验证 Print API；精确物理队列覆盖最终场景但有人、耗材及隐私成本；任意默认设备会丢失边界。

## 需要项目负责人决定

是否先只允许测试虚拟打印机？是否确需真实物理输出，并接受已出纸不可撤回？允许哪些队列/份数与页数预算，网络打印是否等待 ADR-0044，哪些驱动因不可取消对话框维持人工操作？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。接受前不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 决定（2026-11-01）

项目负责人 2026-11-01 确认原话：“按你推荐的来，接受 ADR-0036 到 0045”。按本文“提议的安全调用方式”接受；“仍不能开放的部分”继续排除，也不抵充 4014 完成数。所有候选仍默认关闭，按随产品审阅的精确编译分支逐组开放；逐次审批、scratch 限定与实机验证要求不变。本决定只接受本类别的审阅边界，逐组例外仍须留下批准记录。

## 后续验证与依据

Small/Medium 覆盖队列/页数/份数校验、目的地变化、审批拒绝及禁止自动重印；Large 在测试虚拟队列核对无弹窗、exports 产物、取消和 unknown；真实出纸须每次单独批准。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
