# ADR-0040：对 deprecated 重载采用非弃用路径优先与逐签名例外

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（2026-11-01 接受） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；接受后按本文边界逐组实施 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **0 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

本类首阻为 0；正式缺口中 7 个混合组含 22 条 deprecated 签名，例如 `Backup.Project`、`ProjectManagement.CompressProject`、`NetDefinitionPoint.AddDaisyChain`。另有 54 个整组 deprecated 在分母外。可调用至少一个非弃用重载已满足组口径，不能因此宣称旧重载也已开放。

旧重载可能依赖过期介质、格式、方案或对象语义；在当前版本编译成功也不保证有同样副作用/可恢复性，未来 SDK 还可能删除。将旧签名混进通用重载选择会让模型无意使用较危险分支。

## 提议的安全调用方式

1. 先选同组非弃用重载，逐一列出官方替代项与参数转换；deprecated 保持从默认候选中隐藏。若只能由旧重载完成特定任务，单独登记 SDK/变体/签名、实际需求及厂商替代说明，不能按整个类型放行。
2. 例外先只读，写入必须 scratch、逐次审批、备份与读回；审批明示“已弃用接口”、版本锁定、替代方案及失败恢复限制。参数/返回仍只用编译分支；文件、设置、主数据、交互等交叉约束继续单独审批。
3. 例外仅在已验证版本可用；升级 SDK 时重做存在性、编译与副作用验证。能力不可用报告版本/证据缺口，不把环境缺失当用户违规，也不自动切换到未经批准的旧重载。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

目标版本已移除或没有可编译绑定的旧签名不能凭反射“恢复”。替代方法不算原组已直接可达；deprecated 标记不能靠重命名目录条目删除。

## 备选方案与代价

永不调用弃用重载最稳，但可能缺某些旧任务；无限期全部保留有版本负担；先同组非弃用重载、确需时逐签名例外，兼顾组目标与维护成本。

## 需要项目负责人决定

是否接受非弃用重载优先、旧重载默认关闭？哪些需求值得精确版本的例外？是否确认分母外 54 组不自动计入本次 4014 目标，若将来扩大范围需另行确定分母与支持版本？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。接受前不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 决定（2026-11-01）

项目负责人 2026-11-01 确认原话：“按你推荐的来，接受 ADR-0036 到 0045”。按本文“提议的安全调用方式”接受；“仍不能开放的部分”继续排除，也不抵充 4014 完成数。所有候选仍默认关闭，按随产品审阅的精确编译分支逐组开放；逐次审批、scratch 限定与实机验证要求不变。本决定只接受本类别的审阅边界，逐组例外仍须留下批准记录。

## 后续验证与依据

Small 覆盖选择不回退旧重载、版本错配与参数转换；Medium 覆盖审批/备份失败；Large 对获准旧签名核对实际效果、恢复、文件与设置副作用及支持版本。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
