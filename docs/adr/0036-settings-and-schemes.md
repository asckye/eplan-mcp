# ADR-0036：为设置与方案调用建立全局作用域审批及备份恢复边界

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（2026-11-01 接受） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；接受后按本文边界逐组实施 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **114 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

包括 `Settings.SetStringSetting`、`SettingNode.Write`、`SchemeSetting.ImportScheme/RemoveScheme`、`ProjectSettings.SetNumericSetting` 及使用方案参数的服务；还包括 `UserRights.SetUser/AddRight` 等用户权限状态。设置可能属于项目、用户、工作站或共享公司范围，不能由 scratch 项目参数推断。

用户/工作站设置越出 scratch，可能改变所有项目的导出、校验和默认库；方案导入/删除可能覆盖持久配置，项目 SafetyPoint 不保证恢复这些文件。用户权限写入可能锁住整个工作站的操作。A63 及安全标准已排除这些路径，尚无本批逐签名恢复证据。

## 提议的安全调用方式

1. 先开放经证据确认无副作用的读取；写入逐键/逐方案登记作用域、文件、可写类型和恢复办法，不能只按方法前缀分类。项目级设置必须证明实际写入仅属目标 scratch；全局写入优先放在工程师准备的独立测试用户/工作站环境。
2. 全局写入前导出并备份键值、类型、索引、默认值、方案及受影响配置文件，校验备份可还原；锁定受影响范围并排除并发修改。审批后核对快照；调用后读回、记录差异，finally 恢复并再次核对。进程崩溃需落盘恢复计划，重启后先核验恢复，不能把 finally 当作崩溃保证。
3. 逐次独立审批必须写明“修改用户/工作站设置，影响使用该配置的所有项目”，列出作用域、键/方案、前后值、备份和恢复限制。值中敏感内容脱敏；拒绝、超时或审批过期不执行，恢复失败或执行不明按 ADR-0010 暂停实例并交人处理。
4. 部件库优先显式打开 scratch 文件副本；`PartsService.PartsDatabase` 的全局切换仍受 ADR-0019 禁止。若负责人另选允许临时切换，仅能在隔离环境中经本 ADR 明确接受其对 ADR-0019 的限定修订，再验证选择与恢复，不能把它当作已经接受的“副本规则”。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

不得修改 Host 的安全配置、scratch 根目录、审批开关或审计策略（SEC-02）；本提议不给这些自提权入口。无法完整识别/备份/恢复的共享配置、凭据及权限管理保持不可执行，缺失观测仅报告证据缺口；独立的恢复前提不成立时不能开始写入。不能承诺通过项目撤销恢复全局设置。

## 备选方案与代价

维持只读最容易隔离，但写组留在缺口；把所有设置视作 scratch 写入会低估全局影响；只审批不备份无法恢复；独立测试用户/虚拟机成本较高，但比原工作站临时修改更容易限制影响。

## 需要项目负责人决定

是否接受按明确作用域逐键开放、默认只读及隔离环境要求？是否接受全局写后自动恢复，而非保留变更？是否需要单独允许临时切换部件库，并限定修订 ADR-0019？哪些用户/工作站配置与权限操作必须始终留给人工？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。接受前不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 决定（2026-11-01）

项目负责人 2026-11-01 确认原话：“按你推荐的来，接受 ADR-0036 到 0045”。按本文“提议的安全调用方式”接受；“仍不能开放的部分”继续排除，也不抵充 4014 完成数。所有候选仍默认关闭，按随产品审阅的精确编译分支逐组开放；逐次审批、scratch 限定与实机验证要求不变。本决定只接受本类别的审阅边界，逐组例外仍须留下批准记录。

## 后续验证与依据

补精确作用域解析、恢复计划及审批文字 Small/假 Bridge Medium；Large 验证全局前后快照、并发变更、崩溃后恢复和恢复失败暂停，覆盖 `ApiTryTests`、`NoSideEffectTests` 与相关设置/主数据类。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
