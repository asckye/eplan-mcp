# ADR-0050：Bridge 管道消息拒绝未知字段和重复字段

| 项 | 内容 |
|---|---|
| 状态 | Proposed |
| 日期 | 2026-11-03 |
| 决策人 | 项目负责人（待确认） |
| 门的类型 | 单向门：Host 与插件的 IPC 契约（L3） |

## 背景与问题
手册 SEC-14（MUST）要求命名管道的帧有大小上限，未知字段和重复字段拒绝。合规审计（2026-11-03）结论为"部分符合"：Host 与 Bridge 之间已有当前用户 SID、
受保护 DACL、拒绝远程客户端和长度上限（[ADR-0003](0003-ipc-named-pipe-json-rpc.md)），但 JSON-RPC 帧的解析没有统一拒绝重复成员和未声明成员。
改变 IPC 的接受规则属于 L3，只能先提议。

## 决策驱动因素
- 安全：防止同机进程用畸形帧（重复键、额外键）绕过校验或让两端理解不一致。
- 兼容：Host 与插件同版本发布（插件由同一发行包注册）；跨版本组合本来就不支持。
- 诊断：被拒绝的帧要给出能定位的诊断编号，不能静默丢弃。

## 备选方案
1. 维持现状，靠长度上限和 SID 校验。
2. **两端在 JSON-RPC 帧解析时拒绝重复成员和未声明成员，返回协议错误并记录诊断编号；协议版本号不变（同版本发布），在发布说明中注明。**
3. 升级协议版本号，旧帧兼容一个版本。

## 决策（提议）
选择方案 2：Host→Bridge 与 Bridge→Host 的帧都用严格解析（重复键、未知成员即拒绝），错误按现有协议错误返回并附诊断编号；新增负面测试（重复键、
未知字段、超长）。按入口分片实施，每片 ≤200 行。

## 后果
- **好的**：满足 SEC-14；两端对同一帧的理解一致。
- **坏的或要付出的代价**：今后给帧加字段必须两端同时发布（已是现状）；开发期混用新旧插件会直接报错，需要重新注册插件。
- **后续行动**：负责人确认后按入口分片实施；`docs/architecture/architecture.md` 的 IPC 一节同步。
