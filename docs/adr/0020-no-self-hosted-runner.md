# ADR-0020：不使用自托管 runner：实机测试在开发机上手动运行，插件在开发机上按标签构建后交给发布工作流

## 背景与问题
[M5 设计](../design/2026-10-20-m5-operability.md)（G5、4.9、4.10、Q8）原计划在开发机上以单独的标准用户运行一个自托管 runner：每晚和发布前构建插件，用离线宿主跑 Large 测试，并在发布工作流中构建插件。项目负责人 2026-10-21 决定："这个不用做runner"。

不用 runner 本身已经决定。要决定的是它原来承担的四件事改由什么完成：
1. 每晚和发布前的 Large 测试、发布前的 Agent 评测；
2. 发布时构建插件：插件编译时要引用本机 EPLAN 的 API 程序集，GitHub 托管的 runner 上没有 EPLAN（ADR-0016）；
3. SEC-16 规定"只发布 CI 构建的产物"，插件原来也由发布工作流构建；
4. I1"不需要管理员"的验收：托管 runner 以管理员身份运行，证明不了这一点（M5 设计 4.10）。

改变发布产物的来源属于安全模型（供应链，TB5），是 L3，只能提议。

## 决策驱动因素
- 发布的插件要能追溯到确定的提交，并且有人能核对它没有被替换。
- 不提交 EPLAN 的程序集（它们是 EPLAN 的专有文件）。
- 不增加项目负责人要长期维护的机器和账户。

## 备选方案
1. **开发机手动**：Large 测试和评测由维护者在开发机上手动运行（与目前相同）；发布时维护者在开发机上从标签的干净检出构建插件，跑一遍 Large 测试，把插件和它的 SHA-256 交给发布工作流打包。
2. **把 EPLAN 的程序集放进仓库或 CI 缓存**，在托管 runner 上编译插件：违反 EPLAN 的授权和 CLAUDE.md 第 4 条。否决。
3. **从 XML 文档生成引用程序集的桩**，在托管 runner 上编译：工作量大，桩与真实程序集不一致时只在运行时才暴露。否决。
4. **以后在虚拟机中装 runner**：推迟，需要时另写 ADR。

## 决策
选择方案 1：
- **实机测试与评测**：Large 测试在开发机上手动运行（[testing.md](../standards/testing.md) 第 4 节，现状不变），时机是：合并写入类工具或 Bridge 的改动之前，以及每次发布之前；Agent 评测在发布前和工具描述改动后手动运行。结果附在 PR 或发布说明中。
- **插件的构建**：新脚本 `eng/scripts/release-addin.ps1 -Tag vX.Y.Z`：
  1. 在新建的 worktree 中检出该标签，确认工作区干净、标签已推送；
  2. `dotnet build src\EplanMcp.Bridge.Eplan -c Release`（`EplanSign=false`，ADR-0007），在离线宿主上运行 Large 测试；
  3. 打包插件目录，计算 SHA-256，用 `gh` 上传到该标签的草稿发布；
  4. 脚本只读写那个 worktree 和草稿发布，不改全局设置。
- **发布工作流**：Host、Workbench、安装包照旧在托管 runner 上构建并生成来源证明；插件从草稿发布下载，与发布说明中维护者给出的 SHA-256 比对，不一致就失败；安装包和它包含的每个文件照旧生成来源证明，发布说明写明"插件由维护者在开发机上从标签 vX.Y.Z 构建"。
- **SEC-16** 改为：只发布由标签构建的产物；插件是唯一的例外，由维护者按上面的脚本构建，附 SHA-256。
- **I1"不需要管理员"**：在 M5 第 16 步的干净机器验收中，以标准用户账户验证。
- **撤销**：M5 第 13 步（`live.yml` 与自托管 runner）取消；T23、SEC-26 撤销；TB5 中去掉 runner。

## 后果
- **好的**：不需要新的 Windows 账户、runner 注册令牌和每晚运行的机器；没有"公开仓库的自托管 runner"带来的风险（T23）。
- **坏的或要付出的代价**：
  - 插件的来源证明只能证明"发布工作流收到的就是维护者上传的文件"，证明不了它由哪份源码构建；可信程度取决于维护者的开发机；
  - Large 测试不再每晚自动运行，回归只能在合并前和发布前发现；
  - 发布多了一个手动步骤。
- **后续行动**：
  - M5 设计（G5、4.9、4.10、Q8、第 8 节步骤 13）、开发流程第 7、8 节、testing.md 第 4 节、security.md（TB5、T23、SEC-16、SEC-26）、架构第 11 节按本 ADR 修改；
  - 实现 `release-addin.ps1` 和发布工作流中下载、比对插件的步骤（M5 第 14 步）。
