# ADR-0052：用 `eplan_project_update` 写标题栏用到的项目属性

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-06 |
| 决策人 | 项目负责人 |
| 门的类型 | 双向门（白名单条目可以再撤掉） |

## 背景与问题
按描述或按 PDF 画一整套图时，每一页的标题栏、封面和报表抬头都读项目属性：公司名称、公司地址、项目描述、创建者、项目负责人等。提议时 `eplan_property_set` 拒绝项目对象，`eplan_action_try` 默认也不启用，所以这些字段只能由工程师在 EPLAN 里手填。

复刻 71 页图纸时，封面和全部报表页的抬头都停在模板默认值（`EPLAN GmbH & Co. KG`）。写入白名单属于安全模型，所以这里只提议，等负责人确认。

## 决策驱动因素
- 项目属性只影响显示，不改变器件、连接和结构。
- 结构格式这类属性（10002、10050 到 10064）一改就影响所有设备标识，绝不能放开。
- 现有的 scratch 自动写入、scratch 外审批、撤销和审计规则不应该因此改变。

## 考虑过的方案
1. **白名单加入标题栏属性（推荐）。** 只放下面这份固定清单，其他项目属性仍然拒绝。
2. **工程师每个项目手填一次。** 不改代码，但 AI 无法独立完成一整套图，每个新项目都要人工介入。
3. **默认启用 `eplan_action_try` 调 `XEsSetProjectPropertyAction`。** 范围太大，这个 action 能写任何项目属性。

## 决策
采用方案 1。允许写入的项目属性如下，都是文本：

| ID | 名称 |
|---|---|
| 10011 | 项目描述（多语言） |
| 10013 | 项目编号 |
| 10014 | 代理 |
| 10015 | 公司名称 |
| 10016 | 公司地址 1 |
| 10017 | 公司地址 2 |
| 10020 | 创建者 |
| 10025 | 项目负责人 |
| 10030 | 制作 |
| 10031 | 项目类型 |
| 10032 | 安装地点 |
| 10100 | 客户简称 |
| 10232 | 创建者名称 |
| 10235、10237、10238 | 创建者街道、邮编、城市 |
| 10240 | 创建者电话 |

模板自定义的项目属性（识别名以 `ESS.Project.` 开头）也可以写，比如封面上的电源和控制电压。

规划和执行规则与其他写工具相同：scratch 内自动写入，scratch 外走策略和工程师审批，读回校验，一次撤销，写入审计。

## 后果
- AI 可以独立填好封面和标题栏，整套图不再需要这一步人工操作。
- 这些字段常含客户名称、地址和电话。它们只留在项目里；审计日志按现有规则脱敏，测试和文档不能使用真实客户数据。
- 项目属性的撤销行为要在 scratch 上实测，结论写进 api-notes。实测和本 ADR 不一致时，先改 ADR 再实现。
