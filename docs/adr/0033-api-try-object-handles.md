## 背景与问题

2026-11-01 的缺口分析给出操作层 4014 组中 3004 个未实现组的首个阻塞原因：

| 原因 | 组数 |
|---|---:|
| 所属类型无法到达（拿不到这种对象） | 1851 |
| 返回值类型不受支持 | 368 |
| 其余（生命周期、文件、设置、主数据等，已分别在做） | 785 |

无法到达的类型里，很大一部分是**只能由另一个对象的方法或属性返回**的值对象和辅助对象，例如连接点位置、引脚、路径信息、3D 角点、图层、宏窗口、部件库中的部件。它们没有可以在调用之间稳定定位的持久标识（不能用 `eplan_object_find` 的定位器表示），所以按 ADR-0032 的约束——参数只允许简单值与对象定位器——这些对象既不能作为返回值交回给代理，也不能作为下一次调用的目标。

## 决策

在 `eplan_api_try` 中增加**短期对象句柄**：

1. 方法或属性返回一个不能用定位器表示的对象时，Bridge 把对象放进**本次 EPLAN 会话的句柄表**，返回 `{ "handle": "h:<随机 128 位>", "type": "<类型全名>" }`。
2. 后续 `eplan_api_try` 调用可以把句柄作为目标或参数；Bridge 按句柄取回对象，并核对类型与生成的分发表一致。
3. 句柄的限制：
   - 只在创建它的 Host 会话与同一 EPLAN 进程内有效；EPLAN 退出、项目关闭、Host 重启或 10 分钟未使用即失效；每个会话最多 500 个，超出时最旧的失效。
   - 只指向目标 scratch 项目中的对象；对象所属项目在每次使用时重新核对，不在 scratch 中即 `POLICY_DENIED`。
   - 句柄表不持久化，不写审计以外的任何地方；审计记录句柄的类型和来源调用，不记录对象内容。
   - 主数据（部件库）句柄只在 M9 的部件库副本规则下可用；设置对象的句柄只读。
4. 审批文字显示句柄的类型与来源（"由 <组> 返回的 <类型>"），并照常标注"未验证"。
5. 一次写入调用仍是单个撤销步骤；句柄本身不改变撤销与快照规则。

## 预期效果

缺口分析中"所属类型无法到达"与"返回值不支持"合计约 2200 组；按类型逐个核对，预计句柄可以覆盖其中 800–1200 组。实际数量在实现后由生成表统计。

## 备选方案

- **维持 ADR-0032 的约束**：这约 2200 组保持"不可试"，操作层的可试比例停留在 40% 左右，与"操作层全部补齐"的目标不符。
- **为每种值对象设计专用定位器**：每种类型都要找出稳定的标识规则，很多类型没有；工作量大且仍会遗漏。
- **允许代理直接传对象的内部指针或序列化内容**：不安全，不可验证，否决。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 句柄指向的对象在两次调用之间被 EPLAN 释放或改变 | 每次使用前检查对象有效性与所属项目；无效时报 `PLAN_STALE`，要求重新取得 |
| 句柄被用于非 scratch 项目 | 使用时重新核对所属项目，scratch 外一律拒绝 |
| 句柄表占用内存 | 数量上限与 10 分钟过期；EPLAN 或项目关闭时清空 |
| 代理误以为句柄可以长期保存 | 工具说明与返回文字写明"只在本次会话内有效" |

## 决定

项目负责人于 2026-11-01 接受本 ADR，`eplan_api_try` 增加短期句柄，保持只在 scratch、默认关闭、逐次审批的约束。
