# ADR-0044：对网络调用采用隔离端点、数据清单与不可撤回审批

| 项 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-11-01 |
| 决策人 | 项目负责人（2026-11-01 接受） |
| 门的类型 | 单向门：扩大安全或审批边界后，调用者会依赖；收回需迁移 |
| 级别与影响 | L3；提议对 ADR-0005/0032 的此类限制建立精确例外；接受后按本文边界逐组实施 |

## 背景、范围与风险

负责人目标是 4014 组全部可调用（scratch、逐次审批）。[缺口清单](../eplan/operation-gap-inventory.md)与 [TSV](../../catalog/operation-gaps.tsv)中本类首阻为 **2 组**；计数不等于该类全部重载，也不重复计其他块的交叉约束。

正式缺口的首阻为 `EplApplication.StartEplanRemoteServer` 和 `ProjectManagement.PublishProjectForSmartProduction` 两组；前者涉及服务监听，后者须先查明发布究竟只落文件还是实际发送。其他组的 URL、UNC、数据库服务器参数作为交叉约束，不能因本类只有两组而忽略。

开启监听会改变进程的网络暴露；发布可能发送项目数据或生成带敏感内容的包，数据一旦离开本机无法靠撤销收回。A1/B4 已记录旧 Remote Client 的网络与认证限制，现有 Host HTTP 的 ADR-0018 不自动授权 EPLAN 自己的远程服务。

## 提议的安全调用方式

1. 先查官方精确契约并只读枚举状态；把文件生成与发送分开，能只写 exports 的用 B3 适配。需发送时先生成有界产物，向人展示收件端点、字段/文件清单、大小和哈希，绑定一次审批；只从 scratch 取数，测试先用隔离模拟端点。
2. 端点由工程师配置允许列表，核对协议、主机、端口、解析结果及重定向；禁止模型自行提供凭据、任意 URL 或开启监听所有接口。需要服务端口的接口必须另有已确认的认证、绑定、暴露和关闭设计；不能复用 ADR-0018 的批准代替此决定。
3. 审批明确“向本机外发送/开启网络服务，外部效果不可撤回”，显示范围及后续关闭/撤销发布办法。发送结果不明不自动重发；本地快照只用于确认输入未变，不声称能从远端删除或撤销收到的数据。

所有候选继续默认关闭，使用随产品审阅的精确编译分支；调用前独立窗口逐次审批，展示 unverified、签名、参数、来源及超出 scratch 的具体效果，绑定实例、输入摘要和前置状态；拒绝/取消/过期不执行。审计先行，不能由模型代答或修改策略；审批不免除同项目/路径/许可等独立前提。结果未知或恢复失败沿 ADR-0010 暂停相应目标和实例，不自动重发。

## 仍不能开放的部分

任意端点外传、无保护的全网监听、凭据自动提供与绕过认证不开放；已发送数据不能保证追回。若指定 EPLAN API 不支持限定监听/认证，不能在当前网络边界安全放行，需可验证的外部隔离设计和新的负责人决定。

## 备选方案与代价

维持离线 exports 后由人发送可隔离风险；固定模拟端点可验证调用但不能代表真实服务可用；受控真实端点覆盖业务更完整但有不可撤回后果；任意网络访问不接受。

## 需要项目负责人决定

是否只允许模拟/隔离端点，真实发布由人完成？若允许真实端点，接受哪些数据和不可撤回效果？是否确需 StartEplanRemoteServer，还是保持 ADR-0002 的现有 Host/Bridge 拓扑，另选受支持入口？

本 ADR 只提出该类别的审阅边界；请分别选择接受、修改或维持排除，并记录日期、明确范围和确认原话。其他九类不随之获准；需要逐组例外时另留批准记录。接受前不修改安全标准或运行时策略，不将不可执行项抵充 4014 完成数。

## 决定（2026-11-01）

项目负责人 2026-11-01 确认原话：“按你推荐的来，接受 ADR-0036 到 0045”。按本文“提议的安全调用方式”接受；“仍不能开放的部分”继续排除，也不抵充 4014 完成数。所有候选仍默认关闭，按随产品审阅的精确编译分支逐组开放；逐次审批、scratch 限定与实机验证要求不变。本决定只接受本类别的审阅边界，逐组例外仍须留下批准记录。

实施顺序：在十个类别中最后实施。

## 后续验证与依据

Small/Medium 覆盖端点绑定、重定向、解析变化、数据摘要及重复发送保护；Large 在隔离网络/模拟端点观察实际出站、监听地址、认证和关闭；实际外部服务另经人工批准。

本次仅离线文档盘点，以上机制均为待验证提议，未运行 EPLAN，也不宣称备份、恢复或看门狗已实现。实现前把精确 API 行为的官方/获准 scratch 证据写入 [api-notes](../eplan/api-notes.md)，新增 Large 待验记入[台账](../process/large-pending.md)。缺失或不可读数据只给警告和证据缺口，不据此判违规；独立成立的写保护、审批、权限及恢复前提仍有效。
