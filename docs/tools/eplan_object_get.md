# 工具规格：`eplan_object_get`

`object` / `full` / Read；title 为 Read EPLAN object，四注解依次为 true / false / true / false。 按 eplan_object_find 的精确 `object_type`、`locator` 读取属性；`project` 可省略，`language` 可指定 zh_CN 等代码；`response_format` 为 concise（默认）/ detailed，`limit` 默认 50、范围 1–200，`cursor` 原样续读。 输入对象闭合；locator 必须含 project/page/type/oid/digest。项目、类型、编号、名称/页/位置摘要不符返回 PLAN_STALE，不能按名称改指其他对象。 输出沿用 find 的 project/status/reason/items/cursor/truncated；属性行含 property_id、property_name（字典正式名）、index、status、value、language，详细字段、拒读和多语言回退与 eplan_property_get 相同。遍历该类型全部公开数字 ID，省略索引时只展开已有索引，按 ID/index 排序；不适用、空和拒读行保留，不伪造值。 复用 PropertyReadOperation、运行时 Scope 与多语言助手；PropertyCatalog 分类在取值前检查，路径、联系人、内部属性等拒读。每次主线程调用仅获取一次属性列表，值与列表全部释放；借用对象不释放；无事务或提交（A36/A39）。每块 200 行及两秒软预算，20 秒硬检查；Host 拒绝超过 1 MiB 或无进展的块。 分页、错误、68 类型状态及测试见 [find 规格](eplan_object_find.md)；concise / detailed 双份响应预算分别约 5k / 20k token，游标额外绑定语言与格式。未知类型 INVALID_ARGUMENT；已知但未接入的类型返回 unsupported 及原因。 Large 测试还核对请求前后的设计文件指纹。评测场景：find 后以 locator 分页读取属性，明确显示所用语言、空值与拒读原因。
